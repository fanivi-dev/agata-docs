Product UI follows [Paper → code → Storybook](/design-system/workflow). This page covers only **promoting or changing** something in `packages/ui`.

## Flow

<Steps>
  <Step title="Design in Paper">
    Frame (and variants) in Paper Desktop. Flex, official Astryx semantic tokens, C2. Paper's HTML is never pasted into the package.
  </Step>
  <Step title="Does it belong to the system?">
    If a single feature uses it, keep it in the feature. If it is reused, carry on.
  </Step>
  <Step title="Implement in packages/ui">
    Map the wrapper onto Astryx when a primitive exists. Preserve its props and behavior unless an exact Agata boundary requires an adapter. Use StyleX (`stylex.create` + `stylex.props`) with official Astryx tokens only for leftovers. Keep native compatibility paths narrow and documented.
  </Step>
  <Step title="Storybook">
    Story in `apps/storybook/stories/…` with `autodocs`, StyleX variant `argTypes`, `Default` plus meaningfully different variants. Align the story with the Paper frame.
  </Step>
  <Step title="Document here">
    Update the catalog / patterns / tokens under `apps/docs/design-system`.
  </Step>
  <Step title="PR">
    Include light/dark screenshots and, where relevant, two app themes.
  </Step>
</Steps>

## UI PR checklist

- [ ] Light and dark
- [ ] At least one `data-app-theme` if it uses primary
- [ ] Keyboard and focus visible
- [ ] No forbidden imports (Radix Select, etc.)
- [ ] No Agata token aliases or feature-owned design variables
- [ ] No business logic in the package
- [ ] Docs in this tab updated
- [ ] Storybook updated (and aligned with Paper if the look changed)
- [ ] English only — titles, comments, fixture copy

## Component API

- Stable named exports
- Astryx contracts (`label`, `xstyle`, controlled props) on the stable Agata export
- `xstyle` for StyleX; do not add `className` / `render` bridges or shadcn compound slots
