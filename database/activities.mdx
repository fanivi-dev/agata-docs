## `activity_logs`

Occurrences by date:

| Column | Notes |
| --- | --- |
| `activity_id` | |
| `date` | TIMESTAMPTZ |
| `completed` | |
| `canceled_at` / `cancellation_reason` | |
| soft delete | |

Only activities with `kind = habit` accept logs. The API rejects completions and cancellations for `kind = block`.
It also rejects dates before the creation day; those invalid historical logs are repaired in migration `000038`.

`POST /:activityId/reset-history` (habits only) soft-deletes all `activity_logs` for the habit, sets `current_streak` / `longest_streak` / `completion_rate` to 0, and updates `activities.created_at` to the reset time so the history window matches a newly created habit.

## `activity_images`

Same blob pattern as task_images: store, pathname, etag, position, soft delete.

Activities are unlimited for customers. Private abuse safeguards may return `CAPACITY_GUARD_REACHED`.
