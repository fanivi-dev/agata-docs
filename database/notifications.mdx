### Indexes

- Due: `(status, send_at)` WHERE pending  
- Entity: `(domain, entity_type, entity_id)`
- QStash publish: `(send_at, created_at)` WHERE pending and without a message id

## Relation to domain

`*_scheduled_job_id` fields on tasks, activities, reminders, library, finance recurring, etc. coordinate with this queue / jobs.

Postgres is the source of truth. QStash only wakes the exact callback: the
handler claims the row if `id`, status, and `qstash_deduplication_id` are still
current. Rescheduling, canceling, or retrying rotates the generation, so an
old callback is a no-op.

Go domain: `internal/notifications`.
