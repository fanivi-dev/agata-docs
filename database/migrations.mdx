## Commands

```bash
bun run api:migrate-up
bun run api:migrate-version
bun run api:migrate-force   # only with care
```

## Deploy (API on Vercel)

The API container (`Dockerfile.vercel`) runs `migrate up` in the entrypoint **before** starting the server. With `MIGRATE_DATABASE_URL` (or `DATABASE_URL`) in the Vercel project, every deploy (and every container cold start) applies pending migrations so the prod schema does not lag behind `dev`.

`cmd/migrate up` is a **fast no-op** when the DB is already at the head version (log `status=noop`), so there is no need to skip migrations in the entrypoint to save CPU — the drift risk is not worth it.

`bun run api:build` also runs `migrate up` at the end (useful locally if there is a DSN in `.env.local`).

## Dev reset (destructive)

```bash
# from apps/api or the monorepo flow
go run ./cmd/reset-schema
bun run api:migrate-up
```

Or manually:

```sql
DROP SCHEMA public CASCADE;
CREATE SCHEMA public;
-- then migrate-up
```

## Verify

```sql
SELECT table_name
FROM information_schema.tables
WHERE table_schema = 'public'
  AND table_type = 'BASE TABLE'
  AND table_name <> 'agata_schema_migrations'
ORDER BY 1;
```

## Schema PR checklist

1. Reviewed up/down pair  
2. Indexes for real listing queries  
3. CHECKs for domain enums  
4. FKs with the correct ON DELETE (CASCADE only where it applies)  
5. Docs in `apps/docs/database/…` updated  
6. Dev seed if it introduces required tables  

## Expand / contract

In prod with data: prefer nullable columns → backfill → constraints, instead of destructive rewrites.
