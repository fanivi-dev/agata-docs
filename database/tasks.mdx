## Model

```txt
profile_projects
       │
       ▼
     tasks ──1:1── task_documents
       │
       ├── tasks (subpages; one level max)
       ├── task_assignees (N members)
       ├── task_attention_pins (N personal pins)
       ├── task_comments
       └── task_images
```

### `task_attention_pins` (since `000062`)

| Column | Notes |
| --- | --- |
| `id` | UUID primary key |
| `profile_id` / `task_id` / `user_id` | Unique `(profile_id, task_id, user_id)`; task, profile, and user deletes cascade |
| `created_at` | Stable tie-breaker for the profile attention bar |

The table stores only personal attention intent. The task remains the source of truth for title, status, project, and due date. The API returns pins only when the task is open, active, and `due_date_key <= todayLocalDateKey`. Closing, archiving, soft-deleting, or clearing the due date removes pins; changing the due date preserves them.

### Notable indexes

- By project + deleted/status
- Assignees by user + profile (`task_assignees`)
- Profile + updated
- `due_date_key`
- Reminder date (active)
- **GIN FTS** on `search_blob` (`idx_tasks_search`, config `simple`) — used by list `searchTerm` and `GET …/search`
- **GIN trgm** on `name` (substring / typeahead legacy)
- Recurring series unique removed in `000021`

### Triggers

Insert/update/delete on `tasks` keep `profile_projects.task_count` in sync (`sync_project_task_count_*`). Only root tasks count.

`validate_task_parent` blocks self-references, grandchildren, and profile or project mismatches. `sync_subtask_project_from_parent` propagates a parent project change to its subtasks.

## `task_documents`

ProseMirror body **separate** from the cacheable detail.

| Column | Type | Notes |
| --- | --- | --- |
| `id` | UUID PK | |
| `task_id` | UUID → tasks CASCADE | Unique active 1:1 |
| `profile_id` | UUID | |
| `content_json` | JSONB | Canonical ProseMirror JSON (default empty `doc`) |
| `schema_version` | SMALLINT | Document JSON schema (default 1). Independent of editing `version`. |
| `version` | INT | Optimistic concurrency (default 1) |
| `search_text` / `search_html` | TEXT | Server-derived plain body / legacy HTML projection |
| `created_by` | UUID → users | |
| `created_at` / `updated_at` / `deleted_at` | | |

**GIN** full-text on `search_text` (body). Task list/search mostly uses `tasks.search_blob` (name + body). On `PUT …/document`, the API syncs `tasks.search_blob`.

API: `GET/PUT …/document` uncached. See [Rich text guide](/api/guides/edit-rich-text).

## Subtasks

Since `000041`, the `task_subtasks` table no longer exists. Subtasks are rows in `tasks` and reuse the same document, comments, images, tags, and assignees. First-level collections filter `parent_task_id IS NULL`; global search may return both levels.

The API keeps the `/:taskId/subtasks` endpoints as a relation and quick-create interface, but the returned `id` is also the canonical `taskId` of the subpage.
