### `profile_project_links`

Entity ↔ project (unique per entity). Canonical entity types include `task`, `note`, `library_item`, `nutrition_recipe`, `health_checkin`, `finance_transaction`, and `pomodoro_timer`. Activities are not linked to a project.

The link is polymorphic (`entity_type` + `entity_id`, **no foreign key**), so nothing in the database cascades. Two rules keep the project **Profile links** tab honest:

- **Delete side** — a module that deletes a linkable entity clears its link rows in the same transaction (`postgres.DeleteProjectLinks`). Entities with a trash + restore flow (`task`, `note`, `library_item`) keep the row while in trash and clear it on permanent delete (hard delete, trash purge, retention cron). Entities without restore (`nutrition_recipe`, `finance_transaction`, `pomodoro_timer`, `health_checkin`) clear it on delete.
- **Read side** — `ListProjectLinks` resolves every link against its entity and **skips rows it cannot resolve** (entity soft-deleted or gone), so a trashed entity disappears from the tab and comes back if it is restored. A new linkable entity type must be added to `resolveProjectLinkTitles` or its links stop showing.
