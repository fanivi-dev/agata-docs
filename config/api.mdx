Vercel project for the backend (Root Directory `apps/api`, container runtime / `Dockerfile.vercel`). Config: `apps/api/vercel.json`. Crons at `/api/internal/...`. The frontend calls via `GO_API_URL`.

Legend: **yes** = configured in that environment on Vercel. **no** = not defined there.

Load and validation: `apps/api/internal/platform/config/config.go`. In production (`ENV=production`) it requires `DATABASE_URL` and `CRON_SECRET`.

<Warning>
Names and purpose only. Do not document or commit values.
</Warning>

## By group

### Database

- `DATABASE_URL` — runtime (pooler).
- `MIGRATE_DATABASE_URL` — migrations in the container entrypoint.
- The runtime pool is limited per instance to 10 open connections and 2
  idle by default. Limits can be adjusted with `DB_MAX_OPEN_CONNS`,
  `DB_MAX_IDLE_CONNS`, and `DB_CONN_MAX_LIFETIME_MIN`.

### Runtime

- `ENV` — controls `IsProduction()` and strict validation.
- `APP_ORIGIN` — Next app origin for deep links in emails.

### Sentry

- `SENTRY_DSN` — optional. DSN of the **`agata-api`** project in org `agata-h0`.
  The runtime only initializes Sentry when `ENV=production` **and** the DSN is
  not empty. Locally and in Preview it is ignored even if defined. The project
  may need to be created first by an Owner of the Sentry org. Configure it
  on Production of the **agata-api** Vercel project.

### Crons, internal BFF, and email

- `CRON_SECRET` — `Authorization: Bearer <CRON_SECRET>` on `/api/internal/*` (jobs, bootstrap, billing) and on product **GET/HEAD** with `:profileId` when the BFF serves reads from `'use cache: remote'`. Set the **same value** on the **agata-app** project.
- `RESEND_API_KEY` — if empty, emails are not sent (reminders, budget alerts, invitations). The runtime logs this. The from-name matches the product; the brand color is that of `agata.in` / `updates.agata.in` (`#5351c0`).
- `EMAIL_FROM` — optional. Default `Agata <reminders@updates.agata.in>`. If set, the mailbox is reused in product froms (`Tasks <…>`, `Finance <…>`, …).

### Upstash Redis and QStash

The API uses Redis for session cache and rate limits (limits fixed in code).
The frontend no longer uses it for the Agent quota.

QStash replaces frequent polling of notifications and the Metronome
outbox:

- `QSTASH_CALLBACK_ORIGIN` must point to the environment's API, for example the
  corresponding Preview or Production domain. If unset, the runtime
  uses `VERCEL_URL` of the current deployment.
- Public `/api/qstash/*` routes do not accept a session or `CRON_SECRET`.
  They verify `Upstash-Signature`, the exact `sub`, and the SHA-256 body
  hash with both signing keys.
- Postgres rows are the source of truth. The API uses per-generation
  deduplication identifiers; rescheduling or retrying invalidates old
  callbacks.
- The four credential/origin variables are configured together. A
  partial configuration fails startup in Production. Without QStash
  credentials, hourly recovery still delivers with higher latency.

### Agent credits and Metronome

- `AGENT_CREDITS_ENFORCED` stays off during migration, backfill, and initial reconciliation. With `true`, the local projection blocks at zero and never grants overage.
- The `METRONOME_*` variables are server-only. They are used for `studio:<profileId>` clients, contract/rate card, monthly grants, outbox ingestion, and reconciliation.
- Configure the public webhook at `/api/webhooks/metronome`. The signature uses the `Date` and `Metronome-Webhook-Signature` headers.
- Writes publish immediately to QStash. The
  `/api/qstash/notifications/dispatch` and `/api/qstash/metronome/dispatch`
  callbacks claim a single idempotent row.
- `/api/qstash/failure` releases exhausted deliveries so they can be recovered.
- The only safety cron for these flows is
  `/api/internal/qstash/recover`, once per hour (`7 * * * *` in
  `apps/api/vercel.json`). It dispatches overdue items, republishes missing deliveries, and
  reconciles credits. It stays hourly (not every 2h): the cost of waking
  the container is low compared with the risk of a stuck QStash/credits queue.
- The previous internal dispatch/reconcile endpoints remain
  available with `CRON_SECRET` for manual operation, but they no longer have a
  frequent Vercel Cron.
