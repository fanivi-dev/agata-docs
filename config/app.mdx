Vercel project for the frontend (Root Directory `apps/app`, Next.js framework). Production: [agata.in](https://agata.in). Config: `apps/app/vercel.json` (`ignoreCommand` → `scripts/vercel-should-build.sh` skips builds when the diff does not touch `apps/app` / `packages` / lockfile). Next and Eve use the Node.js 24+ runtime with Turbopack for both `dev` and `build`; Bun remains the package manager. The install command pins Bun 1.4.0 through `bunx` so Vercel can read the repository's version 3 text lockfile without enabling the Bun Functions runtime. Do **not** use Vercel Services at the monorepo root (it breaks App Router; see [Configuration](/config)).

## Local development runtime

The app's `dev` script starts Node with a 2048 KB V8 stack. The deep workspace
layout tree can exhaust Node 24's default 984 KB stack during development SSR,
causing a recoverable `Maximum call stack size exceeded` error and a client
rendering fallback. This setting is limited to the development command.

The Bun patch for Next 16.3.5 forwards `--stack-size` to the dev server child
through `execArgv`. Next's unpatched flag formatter puts it in `NODE_OPTIONS`,
where Node rejects it. Recheck this patch when upgrading Next; the temporary
diagnostic preload is not part of the app's startup.

Legend: **yes** = configured in that environment on Vercel. **no** = not defined there.

## By group

### Auth (Better Auth + Postgres)

- `DATABASE_URL` — runtime DSN (e.g. PgBouncer / port 6432). Point this at the pooled endpoint when the provider offers one.
- `PG_POOL_MAX` — shared pool ceiling per Next/Eve process (default 5). Better Auth, billing, Eve chat persistence, Eve memory, and Eve security share that one pool in their process boundary.
- Eve channel auth memos Better Auth `get-session` + studio membership for 30 seconds per cookie/studio hash. Ownership claims still run on every request.
- `BETTER_AUTH_SECRET` — at least ~32 characters in real environments.
- `BETTER_AUTH_URL` — base URL Better Auth uses for callbacks.
- **OAuth host:** the Google `state` cookie is host-only. Social login must start and finish on the same origin as `BETTER_AUTH_URL` (prod → `https://agata.in`). Opening Google from a `*.vercel.app` host and returning to `agata.in` causes `state_mismatch`. In production use the canonical domain; in Preview, OAuth is only reliable if `BETTER_AUTH_URL` / `NEXT_PUBLIC_SITE_URL` match the preview host (or you redirect to the canonical host before `signIn.social`).
- `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` — both or neither; if missing, Google OAuth is not registered.
- `APPLE_CLIENT_ID`, `APPLE_APP_BUNDLE_IDENTIFIER`, `APPLE_TEAM_ID`, `APPLE_KEY_ID`, and `APPLE_PRIVATE_KEY` — full set to register Apple. The client-secret JWT is generated at runtime and never exposed to the client.
- `RESEND_API_KEY` / `EMAIL_FROM` — verification and password-reset delivery via Resend. Default from: `Agata <reminders@updates.agata.in>`. HTML uses brand color `#5351c0`. Email verification is **required** only when `VERCEL_ENV=production`.

### Go API

- `GO_API_URL` — base URL of the **api** project (server-side). On Vercel: the api deployment URL; locally: `http://localhost:8080` (or the code default if unset). In `next dev`, a remote URL is ignored and `http://localhost:8080` is used so seed login does not talk to an API that cannot see the session.
- BFF→Go auth (writes + user-scoped reads): Better Auth session Bearer.
- BFF→Go auth (`/api/internal/*` + shared cacheable reads): `Authorization: Bearer <CRON_SECRET>` — same secret as crons on **agata-api**. Membership/section is validated in Next **before** `'use cache: remote'`.
- Internal Next routes without a cookie: the proxy lets through `/api/internal/eve-cache` (Better Auth session bearer in the handler).

### Feedback hub (`/feedback`)

- `FEEDBACK_ADMIN_EMAILS` — comma-separated emails of product owners / operators. If the session email matches, the hub opens without a password.
- `FEEDBACK_ADMIN_PASSWORD` — optional shared unlock. Comparison is timing-safe and issues a signed httpOnly cookie (HMAC-SHA256 with `BETTER_AUTH_SECRET`, 30-day TTL). Requires `BETTER_AUTH_SECRET`.
- Set **at least one** of the two on Preview and Production of the **agata-app** project. With neither, the gate UI explains which variables are missing (it does not invent values) and nobody can read feedback.
- Reads go to `GET /api/internal/feedback*` with `CRON_SECRET`, so that secret must also be present.

### Blob

- `BLOB_READ_WRITE_TOKEN` — required for private uploads/deletes in server actions (Next only; the API does not use Blob).
- `BLOB_DEV_*` prefixes (preview) vs `BLOB_*` (production) for store and webhook identity.

### Public URLs

- `NEXT_PUBLIC_APP_URL` / `NEXT_PUBLIC_SITE_URL` — same origin in prod (marketing + app).
- `NEXT_PUBLIC_DOCS_URL` — Docs7 origin. Unset → `https://docs.agata.in`. `/docs` and `/docs/*` on the app 308 to that host. Add `docs.agata.in` as a Docs7 custom domain (Free). Do not add it as a Vercel project domain; CNAME DNS to the target Docs7 shows.

### Billing (Stripe)

All `STRIPE_*` vars are required to load the plugin. The initial checkout uses only the plan Price; extra quantities are managed later from Billing. Production webhook: `https://agata.in/api/auth/stripe/webhook`.

The Next app no longer needs `UPSTASH_REDIS_REST_URL` or `UPSTASH_REDIS_REST_TOKEN` for Agent. The old `ai:msgs:d:…` keys expire by TTL.

### Public legal identity

The `LEGAL_OPERATOR_*` variables feed `/legal-notice`, `/privacy`,
`/terms`, and `/cookies`. Although they are configured as server variables, their
values are rendered publicly: do not use addresses or data the operator
does not want published.

Do not enable charges until at least `LEGAL_OPERATOR_NAME`,
`LEGAL_OPERATOR_TAX_ID`, and `LEGAL_OPERATOR_ADDRESS` are complete. `LEGAL_OPERATOR_REGISTRY`
can stay empty for a sole trader not listed in a commercial registry. Keep `LEGAL_CONTACT_EMAIL` on an operational mailbox.

### Agent (Eve), dictation, voice, and image generation

- **Agent chat:** Eve runtime (`withEve` in Next), UI at `/agent`, channel `/eve/v1/*`, persistence in `eve_*` tables.
- **Tool routing:** `EVE_TOOL_ROUTING_MODE=progressive` enables bounded direct-tool exposure. An unset value or `legacy` preserves the full section-gated catalog. This is a server-only rollout switch and the one-setting rollback.
- **Model routing:** `EVE_MODEL_ROUTING_MODE` is `control`, `shadow`, or `routed`. Unset uses `control` until the provider-backed rollout gate passes. `routed` uses Grok 4.1 Fast Non-Reasoning for routine work, Fast Reasoning for risk or tool failure, and one Grok 4.6 rescue. `shadow` logs the proposed route without changing the production model. Gateway `402`/`429` fail the turn; a turn already accepted by the BFF still consumes its credit. Warning thresholds for the monthly inference envelope are 50%, 75%, and 90%.
- **Tool result UI:** an unset `NEXT_PUBLIC_EVE_TOOL_RESULT_UI_MODE` or `structured` renders semantic cards, rows, summaries, and tool states. `legacy` restores generic receipts without changing execution, approvals, or stored history. This browser-visible value is compiled into the client bundle and rolls out independently from tool routing.
- **Agent dictation:** server action with AI SDK `transcribe` via AI Gateway (`xai/grok-stt`).
- **Agent realtime voice:** `POST /api/agent/voice/token` validates chat, membership, and an active credit reservation before issuing a 30-second `vcst_` client secret with `gateway.experimental_realtime.getToken` for `xai/grok-voice-think-fast-2.0`. The browser connects to the Gateway WebSocket; audio does not pass through Next. Issuing client secrets requires `AI_GATEWAY_API_KEY` in Preview, Production, and local; project OIDC does not replace this key.
- Image generation in Activities: server action with AI SDK `generateImage` via AI Gateway (`bfl/flux-2-flex`). On Vercel it uses project OIDC; locally you may need `AI_GATEWAY_API_KEY`.

### Sentry (errors, tracing, source maps)

Sentry org: `agata-h0`. Next.js project: **`agata`**.

- `NEXT_PUBLIC_SENTRY_DSN` — DSN of the `agata` project embedded in the client. The SDK only reports when `VERCEL_ENV=production`.
- `SENTRY_DSN` — same DSN for server/edge instrumentation. Server-only. Also ignored outside Production.
- `SENTRY_ORG` / `SENTRY_PROJECT` — `agata-h0` / `agata`. Used in the **Production build** to upload source maps (not in Preview or local).
- `SENTRY_AUTH_TOKEN` — organization token for releases/source maps in the Production build. Do not expose it to the client or commit it.

Sentry is **off in local and Preview** even if the DSN is defined. `withSentryConfig` (tunnel `/monitoring` and source maps) only runs when `VERCEL_ENV=production`.

Sampling in Production (to limit Active CPU of the `/monitoring` tunnel): traces `0.05`, session replay `0.02`, replay on error `1.0`.
